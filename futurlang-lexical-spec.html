1. Purpose

The purpose of the FuturLang Lexical Specification is to provide a standardized method for converting naturally ambiguous human-language vocabulary into explicit, numbered semantic lexical units.

One FuturLang lexical identifier SHALL correspond to one defined lexical sense.

Instead of representing a polysemous word as a single token:

bank

FuturLang represents its distinct senses as:

bank0
bank1
bank2
...

Each identifier is associated with exactly one definition within a specified lexical database.

2. Fundamental Lexical Model

A FuturLang lexical entry consists of:

LANGUAGE : LEMMA : PART-OF-SPEECH : SENSE-ID

A compact representation is:

lemmaN
  • lemma = the source-language dictionary lemma
  • N = the zero-based sense identifier

Examples:

EN:bank:noun:0
EN:bank:noun:1
EN:bank:verb:0

Abbreviated forms may be used when the language and grammatical category are already established.

3. Zero-Based Numbering

FuturLang SHALL use zero-based indexing:

0 = first recognized sense
1 = second recognized sense
2 = third recognized sense
3 = fourth recognized sense

Example:

light0
light1
light2
light3

Zero-based indexing is intended to make the lexical system convenient for computational implementations.

4. What Constitutes a Distinct Sense?

A new numerical identifier SHALL be created when two uses of a lemma represent sufficiently different concepts that substituting one definition for the other changes the semantic interpretation. 

bank0 = financial institution
bank1 = land alongside a river

Closely related contextual or grammatical uses SHOULD remain under the same sense unless the selected lexical authority explicitly distinguishes them.

FuturLang therefore does not automatically create a new identifier for every possible contextual variation.

5. Part-of-Speech Separation

Different grammatical categories SHALL normally receive separate lexical identifiers. 

EN:light:N:0
EN:light:ADJ:0
EN:light:V:0

For example:

light0 = illumination
light1 = not heavy
light2 = ignite

The fully specified representation is preferred for computational applications.

6. Recommended Canonical Syntax

The canonical FuturLang lexical identifier SHALL be:

LANG-LEMMA-POS-SENSE

English examples:

EN-bank-N-0
EN-bank-N-1
EN-bank-V-0

French examples:

FR-banque-N-0
FR-rive-N-0
FR-léger-ADJ-0

This form avoids collisions between identical spellings and makes the lexical metadata explicit.

7. English Rules

For English, FuturLang SHALL:

  1. Preserve the dictionary lemma.
  2. Normalize capitalization unless capitalization carries semantic significance.
  3. Separate parts of speech.
  4. Separate dictionary-defined senses.
  5. Number senses starting from 0.
  6. Preserve homographs as separate lexical families where appropriate.
  7. Record the dictionary/source used to establish the senses.
EN-bank-N-0 = financial institution
EN-bank-N-1 = land bordering a river
EN-bank-N-2 = mass or collection of similar objects
EN-bank-V-0 = place money in a financial institution
EN-bank-V-1 = tilt an aircraft

8. French Rules

French SHALL follow the same semantic numbering principle. 

FR-banque-N-F-0 = financial institution
FR-rive-N-F-0 = riverbank
FR-feu-N-M-0 = fire
FR-feu-N-M-1 = flame

French grammatical gender SHOULD be recorded where relevant.

Adjectives SHOULD use one lexical identity for their inflectional family rather than creating separate semantic senses for masculine, feminine, singular, and plural forms.

9. Morphology

FuturLang SHALL distinguish lexical identity from surface form. 

run0
runs0
running0
ran0

These SHOULD normally map to:

EN-run-V-0

with morphology represented separately:

surface_form = ran
lemma = run
sense = 0
tense = past

10. Homonymy vs. Polysemy

Polysemy

One lexical item has several related meanings:

head0 = anatomical head
head1 = leader
head2 = top or front portion

Homonymy

Two semantically unrelated lexical items happen to have the same surface form. 

EN-bank-N-A-0
EN-bank-N-B-0

A visible shorthand such as bank0 may still be used when the underlying ontology preserves the distinction.

11. Definition Requirement

Every FuturLang sense identifier MUST have exactly one canonical definition.

Bad:

bank0 = bank

Preferred:

bank0 = financial institution

A definition should identify the semantic concept rather than merely repeat the ambiguous lemma.

12. Context Examples

Each sense SHOULD have at least one example sentence.

EN-bank-N-0
Definition: financial institution
Example: I deposited the money at the bank.

EN-bank-N-1
Definition: land alongside a river
Example: They sat on the river bank.

This creates a distinction between a lexical definition and a usage example.

13. Cross-Language Mapping

English and French senses SHALL NOT be assumed to correspond one-to-one. 

EN-bank-N-0 → FR-banque-N-0
EN-bank-N-1 → FR-rive-N-0

FuturLang SHOULD maintain explicit semantic mappings instead of assuming that similarly numbered words are automatically translations.

14. Translation Equivalence

Translation relationships SHALL be represented separately from lexical identity. 

EN-house-N-0
Definition: a building intended for human habitation

FR-maison-N-0
Definition: a building intended for human habitation

translation_equivalent(
    EN-house-N-0,
    FR-maison-N-0
)

This allows FuturLang to distinguish lexical identity, semantic equivalence, and translation equivalence.

15. No Assumption of Perfect Translation

The system MUST allow:

1 English sense → multiple French senses
multiple English senses → 1 French lexical unit
English sense → no exact French equivalent

Semantic categories need not partition concepts identically across languages.

16. Semantic Identifier vs. Dictionary Order

The initial sense number MAY reflect the ordering of a selected authoritative dictionary, but source ordering SHALL NOT be treated as the permanent semantic identity. 

source_sense_id = 1
futurlang_sense_id = 0

Maintaining both identifiers protects the FuturLang system if a source dictionary changes its ordering.

17. Immutable IDs

Once a FuturLang identifier has been publicly assigned, its semantic identity SHOULD remain stable within the relevant ontology. 

EN-bank-N-0@1.0
EN-bank-N-0@2.0

If a definition changes substantially, a new version SHOULD be created rather than silently changing the meaning of an existing identifier.

18. Semantic Versioning

The lexical database SHOULD use:

MAJOR.MINOR.PATCH
Version componentPurpose
MAJORConceptual restructuring or incompatible semantic changes.
MINORAdditions such as new senses or mappings.
PATCHCorrections to metadata, spelling, examples, or references without changing semantic identity.

19. Canonical Record

A complete FuturLang lexical record SHOULD contain:

{
    language,
    lemma,
    part_of_speech,
    sense_id,
    definition,
    examples,
    morphology,
    synonyms,
    antonyms,
    translations,
    semantic_domain,
    source_dictionary,
    source_sense_id,
    version
}

Example:

{
    language: "EN",
    lemma: "bank",
    part_of_speech: "N",
    sense_id: 0,
    definition: "financial institution",
    examples: [
        "I deposited the money at the bank."
    ],
    semantic_domain: "FINANCE",
    source_dictionary: "SOURCE-DICTIONARY",
    source_sense_id: 1,
    version: "1.0.0"
}

20. The FuturLang Principle of Lexical Disambiguation

The core mathematical principle is:

∀ Lᵢ, |Meaning(Lᵢ)| = 1

Ordinary language may represent:

word → {meaning0, meaning1, ..., meaningn}

FuturLang transforms this into:

word0 → meaning0
word1 → meaning1
...
wordn → meaningn
FuturLang does not attempt to eliminate semantic complexity; it makes semantic complexity explicit.

21. Core Example

Ordinary English:

I went to the bank.

can be ambiguous.

If the intended meaning is a financial institution:

I went to the EN-bank-N-0.

If the intended meaning is land beside a river:

I walked toward the EN-bank-N-1.

The ambiguity is therefore moved from the lexical token into the explicit selection of a semantic identifier.

22. Proposed FuturLang Dictionary Format

EN:bank:N:0 | financial institution
EN:bank:N:1 | land bordering a river
EN:bank:N:2 | organized collection or group
EN:bank:V:0 | place money in a financial institution
EN:bank:V:1 | tilt an aircraft

FR:banque:N:F:0 | financial institution
FR:rive:N:F:0 | land bordering a river
FR:feu:N:M:0 | fire
FR:feu:N:M:1 | flame
FR:feu:N:M:2 | firing of a weapon

The long-form notation is preferred for the formal specification, while shorthand such as bank0 may be used in ordinary FuturLang text.

23. Ultimate Goal

The long-term objective of FL-Lex is not merely to give ambiguous words numbers. It is to create a language representation in which lexical tokens have explicit, stable, machine-addressable semantic identities, allowing English, French, and eventually other human languages to be mapped into a common conceptual system. 

Human Language
       ↓
Morphological Analysis
       ↓
Lemma Identification
       ↓
Part-of-Speech Identification
       ↓
Sense Identification
       ↓
FuturLang Semantic Identifier
       ↓
Universal Concept / Ontology
EN-bank-N-0 and FR-banque-N-0 should not merely be treated as translations; they can be mapped to a shared FuturLang Concept ID when their semantics are determined to be equivalent.

Normative Keywords

In this specification, SHALL indicates a mandatory rule, SHOULD indicates a recommended rule, and MAY indicates an optional implementation choice.
